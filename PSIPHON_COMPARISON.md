# Psiphon integration comparison (engineering notes)

References examined: PattNG `22927868a4f8aca2422db229148b24a6dd35d20e`, its Aether submodule `d58f9d568083129ce2c767c85054021eb3ee6a38`, and the console client pinned by Aether, `CluvexStudio/psiphon-tunnel-core@83aa73b9b982e7421e00117f5b0c5aceb5dda452`. Baseline Manjaniq was `64b154fd84d678658c93c6e8acffe8e738add478`. These are source comparisons, not a claim that the user's network or device has been diagnosed. PattNG is GPL-3.0; its source and assets were consulted, not copied. The separately built Psiphon helper is GPL-3.0; see `THIRD_PARTY_NOTICES.md` and the helper's license and dependency notices in the APK.

| Build and helper packaging | `.github/workflows/build.yml`, `compile-psiphon.sh` and `aether/psiphon-build.sh` build the pinned console client as a static Linux ELF and package it in the extracted native-lib directory. | `scripts/ci/build_helpers.sh` uses the same pinned upstream build script and ABI targets. A clean install consequently had no shipped bootstrap entries. The new build verifies the issuer's signed package; the app stages it privately, never overwrites a supplied list and retains a last-known-good verified copy. | **Confirmed gap:** without cached entries, discovery depends on remote access. It can prevent bootstrap on a network blocking that fetch; no device log proves it was the user's failure. |
| Signature and entry format | `core/PsiphonServerList.kt` verifies the zlib/JSON RSA-SHA256 package and reads ISO regions from hex-encoded entries. | Existing verifier used the same Aether key; build and runtime verification now precede staging, with bounded reads and a content-based cache key. `--psiphon-server-entries shipped-list` resolves to decoded entries; disabling the bundled list no longer silently adds it back. | A missing, corrupt or wrong-key list is unusable; fallback remains cached servers or remote discovery. |

JNI and process paths both use the same runtime argument generation. | Failure to execute, write state, import entries, or reach a usable server can prevent a tunnel. A running process or bound port alone is not proof of connection. |
| Android trust and DNS | PattNG `AetherCoreManager.kt` supplies Android Conscrypt/system CA directories and a Psiphon overlay containing alternate DNS resolvers. | Baseline Manjaniq already supplies `SSL_CERT_DIR` and the same `DNSResolverAlternateServers` overlay through `runtimeEnvironmentMap`; JNI allows `SSL_CERT_DIR` and `AETHER_*`. The pinned client's `common/resolver/resolver.go` uses these alternatives when system DNS servers are unavailable. Explicit user config is not overwritten. | Missing roots or DNS can cause failure on Android, but their presence in baseline makes them an unproven cause here. Public DNS alternatives can themselves be filtered. |
| Ready, notices and lifecycle | Aether waits for a positive `Tunnels` notice and a SOCKS port; `AvailableEgressRegions` is a candidate report, while `ConnectedServerRegion` is the connected server's reported region. | Baseline Rust printed some nonterminal warnings/errors with the same `[-] psiphon: ` prefix that Android `chainEndReasonOf` treats as carrier termination; the monitor cancels the job on that prefix. Now only actual termination retains it; safe fixed notice categories, tunnel transitions and country-only HTTPS exit reporting are emitted without raw client data. | **Confirmed logic defect:** a non-filtered recoverable notice could cancel a session. Whether this occurred in the user's session is unknown. Positive tunnel count is not proof of external traffic. |
| Country selection and persistence | `AetherEditorRepository`, `ServerUiState`, `AetherFmt` and `ServerAetherActivity` combine list regions with the client's later `AvailableEgressRegions`, show localized country labels, and retain ISO codes in the profile/URI. | The existing pipeline is retained. The selector now covers all Psiphon placements, uses the active app locale, preserves a saved unlisted value, and converts codes with `Locale.ROOT`. Any is stored as null/empty. Existing JSON and import/export fields remain intact. | An unavailable candidate can fail to connect; a list of candidates is not a promise of reachability. A missing/incorrect region changes selection, not proof of an observed exit. |
| Client region semantics | The pinned client `psiphon/config.go` documents `EgressRegion` as ISO alpha-2, with `""` meaning any; `dataStore.go` filters server entries by that value. | Profile → `--psiphon-region` → CLI `AETHER_PSIPHON_REGION` → `build_config` → `EgressRegion`; Any omits the flag and the default string is empty. In reverse mode Psiphon carries WARP, so WARP is the final exit. | A selected server region is not independently verified IP geolocation, and the final exit differs in reverse mode. |

## Building and evidence

Run `python3 scripts/ci/fetch_psiphon_servers.py` before a local APK build; it needs OpenSSL and network access to the URL in vendored Aether. The generated signed data and helper notices are ignored by Git. Failure to fetch or authenticate the list fails the CI build rather than publishing a silently incomplete Psiphon APK. A stale or user-supplied list is not overwritten by an invalid update.

The deterministic tests exercise signature checking, region round-trips, Android UI and persistence, helper execution, native configuration, notice classification and tunnel-count state transitions. CI's additional bounded live probe tries Any and two regions from the actual signed list. It records positive tunnel/ready notices separately from a TLS-authenticated HTTP response through the app's SOCKS listener and the trace's observed country. Timeouts, failed HTTPS and mismatches are recorded as such; the exploratory result is not a network-dependent build gate. No raw IP, credentials, server entry or trace body is included in the summary. A successful emulator probe still does not establish that a particular user's network/device will work.
